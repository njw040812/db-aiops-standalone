# 项目规划（现状版）

> 这是一份「做了什么、没做什么、下一步做什么」的记录，不是最初的目标清单。
> 初版规划里的三语言实现、LangGraph、Prophet、向量库均未落地，已从文档中移除。

---

## 1. 定位

面向**数据库运维 / SRE 岗位**的个人项目，用 Python 把一个 DBA 日常的故障处理流程
（告警 → 根因 → 修复提案 → 变更审批 → 执行 → 审计）做成可运行、可测试、可回放的系统。

不是生产级控制面，也不替代 DBA 做 L2 决策。

## 4. 非目标

- 不做通用 APM、日志平台、CMDB；
- 不在没有审批的情况下自动执行 L2 操作；
- 不把「模拟执行成功」包装成「生产已验证」；
- 不声称有线上 MTTR 收益——评测是合成数据。

---

## 5. 验收标准

1. `python -m core.orchestrator` 输出 resolved，5 个节点全部 completed；
2. `python -m pytest` 全绿；
3. `python -m benchmarks.detect_eval` 可复现 README 中的表格；
4. 审计 `verify` 返回 ok；
5. API `/docs` 可打开，`/metrics` 有数据。

---

## 6. 已知风险

| 风险 | 应对 |
|------|------|
| 面试官质疑「没有 LLM」 | 明确说明是规则+贝叶斯，讲清可扩展点，不硬蹭 |
| 面试官质疑「模拟执行」 | 展示执行器抽象、白名单、审批门禁，说明真实执行是配置项 |
| 合成数据不代表生产 | 主动说明数据来源与局限，强调方法论 |
| 单机状态 | 列入 roadmap，不掩饰 |
